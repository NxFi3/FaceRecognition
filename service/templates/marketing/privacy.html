{% translate "1. Two separate categories of information" %}

{% translate "The commercial portal keeps school account details, email, organization name, orders, payment status, subscriptions, authorized devices and support requests. Student records, face templates, attendance and event images remain in the school computer's local database and files. These are not used for marketing or public demonstrations." %}

{% translate "2. Daily processing stays local" %}

{% translate "The current version recognizes and records attendance locally. Face images are not uploaded for daily processing. The public website demo uses only synthetic data. Cloud inference is not a currently purchasable product." %}

{% translate "3. Cloud backup requires consent" %}

{% translate "The school must confirm manual uploads or explicitly enable automatic uploads. New complete backups are encrypted before upload using the school's 256-bit key; the server never receives that internal key. Backups include face templates and event images, so consent must cover this content." %}

{% translate "Legacy SQLite backups created before this format have server-side encryption only and can be decrypted by an operator holding the server key. Existing backups are never silently converted or deleted. A new backup and the deletion policy for old copies must be chosen explicitly." %}

{% translate "4. School responsibility and recovery keys" %}

{% translate "The school must arrange authorized use, notices and student/guardian consent under applicable rules, designate authorized staff and limit access to computers and files. The recovery-key file is not password-encrypted. Keep two secure copies on protected storage separate from backups. Without the key, the vendor cannot recover a new encrypted backup." %}

{% translate "5. Retention and deletion" %}

{% translate "Local records remain until an authorized school action. Capacity archiving does not delete face templates or historical records, and does not disable recognition in the pilot. Student retention and deletion must follow school policy. Deletion can be irreversible; assess legal and recovery needs first." %}

{% translate "Cloud backups default to the latest seven copies and a 1 GiB school quota, which a plan or agreement may change. Account holders can delete selected service copies. Downloaded files, local rollback data and cold server backups are separate copies; deleting one does not automatically erase every location. Server retention and deletion deadlines must be agreed before the pilot. Immediate deletion from every medium is not claimed." %}

{% translate "To minimize unnecessary business information, an operator retention command can anonymize handled contact details and old closed-ticket text and delete old sent emails. Its default threshold is 365 days. Without the apply option it reports a dry run; operators must schedule it. It does not delete financial, subscription or audit records. Account deletion and retention bases require authorized and legal review." %}

{% translate "The hosting location of business records and backups, and any transfer away from the school, must be disclosed in the deployment agreement. This text does not claim hosting in a particular country or data center." %}

{% translate "6. Export and access after expiration" %}

{% translate "Subscription expiry does not delete school data. CSV export and local recovery remain available to authorized staff. Active accounts can download previous backups even after subscription expiry. If an account is disabled, access requests require verification of school authority." %}

{% translate "7. Security and limitations" %}

{% translate "Deploy service connections over HTTPS. School isolation, access controls, license signatures and backup encryption are protections, not a guarantee of zero vulnerabilities. The application does not fully encrypt local databases, CSV exports or recovery copies. Dedicated Windows accounts, ACLs and disk encryption are required. OS administrator access can change the desktop application's protection boundary." %}

{% translate "8. Cookies, demonstrations and marketing analytics" %}
